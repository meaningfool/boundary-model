# Open list

## Round 1: providers of the Level 1 boundaries

Providers: **Executor** (the only provider of the five Level 1 boundaries).

### Executor: parts and verdicts

Component test (use-boundary-model): keeps state only it changes, or makes decisions only it makes, and the other parts reach it only through what it exposes.

1. **Product server** (apps/local/server; apps/hosted/server, composed by apps/hosted/self-host and apps/hosted/cloud; packages/app-management/src/http.ts and contracts; packages/mcp-auth; packages/authorization). PASS. Keeps people, sessions, organizations, members, invitations (Better Auth, apps/hosted/server/src/implementation/auth.ts), groups, app and account access, account links (`hosted_app_account_links`, apps/hosted/server/src/implementation/app-account-schema.ts; `local_app_account_links`, apps/local/server/src/implementation/app-accounts.ts), API keys, agent grants and scoped connections (packages/mcp-auth/src/contracts/grant.ts, connection.ts), tool-call history (`hosted_tool_calls`, apps/hosted/server/src/implementation/tool-call-log.ts), local browser sessions (apps/local/server/src/implementation/session-store.ts). Decides access: "Product-owned authorization. Core SDK ownership is a lookup primitive, not permission enforcement" (AGENTS.md); proofs minted only in apps/hosted/server/src/implementation/proofs/** (lint rule `executor/no-proof-forgery`, .oxlintrc.jsonc, scripts/oxlint-plugin.ts); resolves which accounts a call runs with ("Products resolve the map, never the caller", DEVELOPMENT.md). Consumers reach it only through its HTTP APIs (apps/hosted/server/src/contracts/api.ts `HostedApi`; apps/local/server/src/contracts/dashboard.ts, management.ts) and `/mcp`. Variants: local server and hosted server (Cloud and self-host share apps/hosted/server); they change together (hosted/server <> local/server Jaccard 0.35, work/coupling-areas.txt) and plug the same contracts into the engine (`hooks: ResourceLifecycle`) and code mode (`McpBackend`).
2. **Engine** (packages/sdk: contracts executor.ts, account.ts, apps.ts, tools.ts, schedules.ts, webhooks.ts, events.ts, oauth.ts, registry.ts..., implementation create.ts and the operation modules; packages/app-source as its Git adapter). PASS. Keeps accounts with encrypted credentials, providers, apps, deployments (versions), schedules and scheduled runs, webhooks and webhook sources, events and deliveries, pending tool approvals, OAuth clients, attempts and grants, account connections, tool search listings, workflow runs (`executor_*` tables, packages/sdk/src/implementation/storage-schema.ts). Decides provider identity (packages/sdk/src/implementation/provider.ts), deploy, build and activation order, requirement checks, provider-account OAuth (oauth-protocol.ts). Products reach it only through `createExecutor` and the `Executor` contract (packages/sdk/src/contracts/executor.ts), which apps/local/server/src/implementation/server.ts, apps/hosted/self-host/src/implementation/executor-services.ts and apps/hosted/cloud/src/infrastructure/executor.ts construct with their adapters.
3. **App runtime** (packages/sdk runtime adapters: workerd-*.ts, worker-*.ts, app-runner.ts, remote-app-runner.ts, app-network.ts, app-protocols.ts, app-worker-residency.ts, binding-workerd-apps.ts, workflow-engine-calls.ts...; apps/hosted/cloud/src/infrastructure/runtime.ts, compiler.ts, app-data-worker.ts; packages/apps; packages/app-data; packages/app-cache). PASS. Keeps retained builds, each app's SQLite data (packages/app-data/src/contracts/database.ts) and workflow run state; decides how app code is built (with the `apps` release the app declares) and run in isolates, and what egress it gets (app-network.ts; self-host docs "fetch reaches only public addresses"). The engine reaches it only through the `Runtime` contract (packages/sdk/src/contracts/runtime.ts: build, skills, inspect, index, query, mutate, webhook, workflow, call, checkAccount, migrate), and app bundles only through the recorded, frozen host protocol (packages/apps/src/contracts/protocols/current.ts, packages/apps/protocols/README.md, check `apps:protocols` in scripts/check.ts; lint `executor/authored-code-through-adapter`: "The rest of the SDK runs outside the isolate and reaches an app only by RPC"). Variants: workerd (local, self-host: `workerdApps` from @executor-js/sdk/node) and Cloudflare Dynamic Workers (`cloudRuntime`).
4. **Code mode** (packages/mcp). PASS. Keeps running programs and paused calls (packages/mcp/src/implementation/executions.ts, "live continuations"); decides interpreter limits, tool search pages and how approvals and input pause and resume (packages/mcp/README.md). Products reach it only through `mcp`/`makeMcp` (packages/mcp/src/implementation/server.ts), and it reaches their operations only through the `McpBackend` contract it declares (packages/mcp/src/contracts/backend.ts); it imports from the SDK only schemas, errors and pure helpers, never engine operations.
5. **Public app registry** (packages/app-registry; packages/sdk/src/contracts/registry.ts, publications.ts, implementation/registry.ts, remote-registry.ts; apps/hosted/cloud/src/implementation/publishers.ts). PASS. Keeps publisher scopes, public apps and listings (`executor_public_scopes`, `executor_public_apps`, `executor_public_listings`, packages/app-registry/src/implementation/storage.ts), only it changes them; decides each organization's publisher scope (publishers.ts). Reached only through the `Registry`/`RegistryStorage` contract (registry.ts): Cloud's engine holds its storage (apps/hosted/cloud/src/infrastructure/executor.ts), local and self-host read it over HTTP at api.executor.sh (`remoteRegistry`, apps/local/server/src/implementation/server.ts), and so does the marketing site (apps/marketing/src/contracts/public-apps.ts).
6. **Desktop app** (apps/local/desktop). PASS. Keeps installed app windows with their desktop permissions, and hosted server sign-ins (apps/local/desktop/src/contracts/installed-apps.ts, servers.ts; implementation/installed-store.ts), only it changes them; decides each installed app's desktop permissions. App pages reach it only through the `desktop` bridge (packages/apps/src/contracts/desktop.ts, apps/local/desktop/src/contracts/bridge-channels.ts, preload-app.ts).
7. **Dashboards** (apps/local/web, apps/hosted/web, apps/hosted/cloud/web, apps/hosted/self-host/web, packages/ui, packages/dashboard-start). FAIL: clients that present the product server's API through Effect Atom HTTP calls (DEVELOPMENT.md "Local dashboard"; apps/hosted/web/src/contracts/*). Part of the interfaces.
8. **executor CLI client** (packages/app-management/src/cli.ts, tools-cli.ts, implementation/hosts.ts, node-auth.ts, tools-client.ts, paused-calls.ts; apps/cli). FAIL: relays MCP tool calls and app management requests; what it keeps is sign-in tokens and the session id of a paused call (credentials used only to reach the provider). Part of the interfaces. The `executor service` and `serve` commands start the local product server (apps/local/server/src/bin.ts): set-up, excluded.
9. **Executor app** (packages/app-templates/executor, apps/local/server/src/implementation/executor-app.ts, apps/hosted/server/src/implementation/executor-app.ts). FAIL: an ordinary app whose tools are generated from the host's management API and call it through a linked account (apps/local/server/README.md "Connect an MCP client"; packages/mcp/README.md). It presents the product server's capabilities as tools: an interface.
10. **App templates** (packages/app-templates/src). FAIL: source generators for MCP, OpenAPI and GraphQL imports (packages/app-templates/README.md), a library the product server uses.
11. **Catalog** (packages/catalog). FAIL: reads the official app feed, which another repository writes (packages/catalog/README.md "The feed"), and probes a remote MCP server to prepare its source; "It does not install an app ... or apply product permission rules". An adapter the product server reaches outside services through. (See questions.)
12. **Agent sign-in and grants library** (packages/mcp-auth). FAIL as a Level 2 part on its own: configures the product server's Better Auth OAuth provider (oauth.ts `grantOAuthPlugins`) and wraps the `McpBackend` with a grant (backend.ts `restrictMcpBackend`); the grants live in the product server's sign-in database. Part of the product server, retested in its round.
13. **Authorization policy** (packages/authorization). FAIL: pure schemas and functions (policy.ts) with no state, used in-process by the product server and packages/mcp-auth. A library.
14. **App source adapters** (packages/app-source). FAIL: Git backends (node, Cloudflare Artifacts) the engine keeps app source through (`git: RepositoryBackend`). An adapter.
15. **Live queries** (packages/reactivity), **fumadb-effect**, **utils**. FAIL: libraries.
16. **Telemetry** (packages/telemetry: src, collector, viewer). FAIL: span and log library (src) and diagnostics (collector, viewer): engineering tooling.
17. **Marketing site** (apps/marketing) and **documentation site** (apps/docs). FAIL: public pages, interfaces of the Visitor boundary; the marketing site's app directory reads the public app registry.
18. **Cloud deploy infrastructure, test stages, previews, agent mail** (apps/hosted/cloud/alchemy*.ts, scripts, infrastructure/stage.ts, test-stage-*, pr-preview-*, agent-mail*): tooling.
19. **Executor 1 compatibility** (apps/hosted/cloud/src/implementation/v1-*.ts, infrastructure/v1-api-key-settings.ts): cleanup candidates.

Decision: Executor OPENS (six parts pass). New components for round 2: Product server, Engine, App runtime, Code mode, Public app registry, Desktop app.

## Round 2: the six Level 2 components (Level 3)

### Product server: parts and verdicts
1. **Access** (hosted: apps/hosted/server/src/implementation auth.ts, auth-telemetry.ts, organization*.ts, groups.ts, group-*.ts, resource-*.ts, access.ts, proofs/**, app-accounts.ts, app-account-*.ts, personal-account-schema.ts, profile-app-copies.ts, api-keys.ts, api-key-membership-schema.ts, bearer-access.ts, batch-authentication.ts, connection-policy.ts, oauth-clients.ts, oauth-client-*.ts, mcp-oauth.ts, mcp-connections.ts, desktop-sessions.ts, app-sessions.ts, user-*.ts, managed-*.ts, first-party-oauth.ts, api-oauth.ts, middleware.ts; packages/mcp-auth; packages/authorization; Cloud auth-*.ts, sso.ts, chatgpt-sign-in.ts, emulated-auth.ts, member-limit.ts; local apps/local/server/src/implementation auth.ts, pair.ts, session-store.ts, owners.ts, app-accounts.ts, account-choice.ts, mcp-oauth.ts, mcp-connections.ts, mcp-auth-profiles.ts, app-auth.ts). PASS. Keeps people, sessions, organizations, members, invitations, API keys, agent grants and scoped connections (Better Auth models plus the `mcpGrant` and `mcpConnection` models of packages/mcp-auth/src/implementation/oauth.ts), groups, app and account sharing, OAuth client sharing and account links (`hosted_*` tables written by resource-access.ts, resource-lifecycle.ts, groups.ts, app-accounts.ts, oauth-clients.ts; `local_app_account_links`). Decides who the caller is, what a grant reaches (packages/mcp-auth/src/contracts/grant-enforcement.ts `restrictMcpBackend`) and who may use or manage which app and account (resource-policy.ts, proofs/** under lint `executor/no-proof-forgery`). Other parts reach it through the caller context (`CurrentOrganization`, `CurrentUserId`, `Viewer`, apps/hosted/server/src/contracts/organization.ts, auth.ts), the account middleware `requireAccount` (contracts/account-grants.ts, lint `executor/account-middleware-through-helper`), and the engine's `ResourceLifecycle` hooks (hostedResourceLifecycle in resource-lifecycle.ts).
   Sign-in and sharing were tested apart first and failed apart: access policy reads Better Auth's `member` table directly (resource-policy.ts), revoking an agent grant ends sign-in sessions (packages/mcp-auth/src/implementation/oauth.ts `endSessions`), member removal cascades into group membership (group-schema.ts) and group removal into sharing rows (resource-schema.ts). They share one store and change each other's records, so they form one component.
2. **Activity log** (apps/hosted/server/src/implementation/tool-call-log.ts, tool-call-log-reads.ts, contracts/tool-call-log.ts). PASS. Keeps the history of tool calls (`hosted_tool_calls`, `hosted_tool_call_accounts`), which only these files write or read; the MCP adapter and tool handlers reach it through the recording hook (`ToolCallRecorded`, packages/mcp/src/contracts/backend.ts) and dashboards through its read API (contracts/tool-call-log.ts). Hosted only.
3. **Request handlers** (apps/hosted/server/src/implementation apps.ts, accounts.ts, tools.ts, schedules.ts, webhooks.ts, webhook-setup.ts, workflows.ts, skills.ts, app-data.ts, app-ui.ts, catalog.ts, feedback.ts, api.ts, document.ts, executor-app*.ts...; local dashboard.ts, management, app-management.ts, account-connections.ts, schedules.ts; packages/app-management/src/http.ts and contracts). FAIL: they check access through Access and pass each request on to the engine (packages/app-management/src/http.ts takes `AppManagementHost` = executor + access).
4. **MCP adapters** (apps/hosted/server/src/implementation/mcp.ts, mcp-http.ts, mcp-approvals.ts; apps/local/server/src/implementation/mcp.ts, mcp-approvals.ts; Cloud mcp-forward.ts, mcp-first-use.ts). FAIL: implement `McpBackend` by passing calls on to the engine after Access narrows them.
5. **Catalog and app templates** (packages/catalog, packages/app-templates/src). FAIL: an adapter to the official app feed and to remote MCP servers, and source generators (round 1, parts 10 and 11).
6. **Billing** (Cloud billing.ts, billing-seats.ts, autumn-client.ts, contracts/billing*.ts, autumn.ts). FAIL: an adapter to the billing service; it keeps no subscription state of its own.
7. **Onboarding** (Cloud onboarding*.ts, company-profile.ts; apps/hosted/server/src/implementation/setup-progress.ts). FAIL: a set-up flow whose company profile (`cloud_company_profile`, onboarding-store.ts) only pre-fills the new organization's name and icon.
8. **Email** (Cloud email-messages.ts, email-preferences.ts, welcome-emails.ts, infrastructure/email.ts). FAIL: an adapter to email delivery.
9. **App page addresses** (Cloud app-domain-*.ts, app-domains.ts, infrastructure/app-domain-*.ts; apps/hosted/server/src/implementation/app-addresses.ts). FAIL: routing and certificates for app page hosts, a hosting arrangement.
10. **Organization and user removal, provisioning** (organization-removal*.ts, user-removal.ts, provisioning*.ts, Cloud organization-removal*, executor-app-upgrades.ts, migrations.ts). FAIL: orchestrations that change the records of Access and the engine through them.
11. **Local service control** (apps/local/server/src/bin.ts, main.ts, node.ts, server-process.ts, service-*.ts, launcher.ts, standalone-install.ts, upgrade.ts, update-notice.ts, startup-diagnostics.ts). FAIL: starts, stops and upgrades the local server; set-up, excluded at Level 1.
12. **Cloud edge and site serving** (Cloud edge.ts, entry.ts, host-roles.ts, site-*.ts, homepage*.ts, marketing*.ts, not-found.ts). FAIL: routing by host; the marketing pages it serves are the marketing site interface.
Decision: Product server OPENS (Access, Activity log).

### Engine: parts and verdicts
Accounts and connections (accounts.ts, account-connections.ts, account-health.ts, connection-*.ts, credentials.ts, credential handles at rest, linked-accounts.ts), provider sign-in (oauth*.ts, saved-oauth-clients.ts, stored-oauth-client-credentials.ts), apps, versions and source (apps.ts, create.ts, version-source.ts, git-sources.ts, initial-source.ts, public-files.ts, owners.ts, owner-moves.ts), tool catalog and approvals (tools.ts, tool-pages.ts, tool-approvals.ts, declarations.ts, declaration-config.ts, listings), tool search (tool-search.ts, tool-search-store.ts), schedules (schedules.ts, schedule-worker.ts), webhooks (webhooks.ts, webhook-sources.ts, webhook-http.ts), events (events.ts, event-worker.ts), workflows (workflows.ts), skills (skills.ts, skill-source.ts), storage (storage*.ts, database.ts, reactive-orm.ts).

FAIL each, except as noted: they share one store (`executor_*` tables, storage-schema.ts) and change each other's records: `executor_accounts` is written by accounts.ts, connection-target.ts, oauth.ts, owners.ts, webhooks.ts and workflows.ts; `executor_apps` by apps.ts, initial-source.ts, owners.ts, webhooks.ts and workflows.ts; schedules by apps.ts and schedules.ts; webhook sources by accounts.ts, apps.ts and webhook-sources.ts; OAuth grants by accounts.ts and oauth.ts; events by apps.ts and events.ts. Tool search keeps its listing rows alone (tool-search-store.ts) but they are a derived index of the listings the engine evaluates, rebuilt from them, so it is how the engine finds tools, not a component (see questions). Storage is storage. Decision: Engine stays CLOSED (no two parts pass).

### App runtime: parts and verdicts
1. **Builder** (packages/sdk worker-build*.ts, worker-browser-build.ts, worker-compiled-files.ts, worker-dependencies.ts, worker-json-modules.ts, worker-source-*.ts, worker-wasm-build.ts, workerd-bundle.ts, ui-build.ts, ui-tailwind.ts, contracts/worker-build.ts, ui-build.ts; Cloud compiler.ts, implementation/app-build.ts, build-admission.ts, build-storage.ts, runtime-build-cache.ts, contracts/builds.ts, infrastructure/compiler.ts). PASS. Keeps retained builds (worker-build-storage.ts `retainWorkerBuild`), decides how source compiles (exact `apps` release, limits, dependency rules, Tailwind); reached through `Runtime.build` (packages/sdk/src/contracts/runtime.ts) and, on Cloud, a compiler Worker (contracts/builds.ts).
2. **App sandbox** (packages/sdk app-runner.ts, remote-app-runner.ts, app-runtime.ts, runtime.ts, app-protocols.ts, app-worker-residency.ts, worker-bridge.ts, worker-elicitation.ts, workerd-apps.ts, workerd-client.ts, workerd-entry.ts, binding-workerd-apps.ts, runtime-hop.ts, runtime-connect.ts, evaluated-declarations.ts; packages/app-data; Cloud infrastructure/runtime.ts, runtime-actor.ts, app-data*.ts). PASS. Decides how each app is isolated (one Worker per app and set of accounts, data Workers for apps with a database, residency limits: app-worker-residency.ts; self-host docs) and which host protocol a build speaks (app-protocols.ts); reached only through `Runtime` (runtime.ts) and, across the workerd process, `RemoteAppRunner` (remote-app-runner.ts).
3. **Outbound gateway** (packages/sdk credential-handles.ts, app-network.ts; Cloud app-egress.ts, app-outbound-relay.ts, app-outbound-routes.ts, infrastructure/app-outbound.ts; workerd-entry `AppOutbound`). PASS. Decides what addresses app code may reach and places account credentials only into requests to the hosts a provider declares (`sealAccounts`, `credentialFetch`, `credentialHostMatches`); app code reaches it only through the generated network module and the `CredentialOutbound`/`AppEgress` interfaces (credential-handles.ts).
4. **Workflow engine** (packages/sdk worker-workflow-rpc.ts, workflow-engine-calls.ts, sleep-until.ts, contracts/workflow-runtime.ts; Cloud infrastructure/workflow-runtime.ts, workflows.ts). PASS. Keeps each workflow run's durable step progress (on the platform's workflow service: workerd `Workflows.local`, Cloudflare Workflows), decides step retries and sleeps; the engine reaches it only through `WorkflowRuntime` (start, status, terminate) and it calls back only through `WorkflowHost` (workflow-runtime.ts).
5. **Apps framework** (packages/apps; packages/app-cache). PASS. Runs inside each app's isolate; keeps the app's own data (applies its SQL migrations and serves `ctx.sql`, packages/apps/src/implementation/host.ts, sql.ts), decides input validation, approval enforcement and query/mutation storage rules; the sandbox reaches it only through the recorded host protocol (packages/apps/src/contracts/protocols/current.ts `HostRequest`; lint `executor/authored-code-through-adapter`).
6. **App data store** (packages/app-data, Cloud app-data-worker.ts). FAIL: the Durable Object facets that hold each app's SQLite database; app code changes it directly through `ctx.sql` and the framework applies its migrations (packages/apps/src/implementation/host.ts), so it is storage the framework writes, supervised by the sandbox.
7. **Protocol adapters** (app-protocols.ts, packages/apps/protocols/*.json). FAIL: convert messages for bundles of earlier protocols; adapters.
Decision: App runtime OPENS (Builder, App sandbox, Outbound gateway, Workflow engine, Apps framework).

### Code mode: parts and verdicts
Tool server (server.ts), program executions (executions.ts, program-scheduler.ts), program runner (execute.ts over @opencode-ai/codemode), skills and events passthrough (skills.ts, skill-catalog.ts, events.ts), diagnostics (diagnostics.ts, telemetry.ts). Executions keep the running programs and paused calls; the runner runs within an execution and shares its state; the rest pass requests on to `McpBackend`. Cloud keeps the same state in a Durable Object (apps/hosted/cloud/src/infrastructure/mcp-session*.ts, mcp-interaction-store.ts). One part passes at most. Decision: Code mode stays CLOSED.

### Desktop app: parts and verdicts
Installed apps (installed-apps.ts, installed-store.ts, launchers.ts, install-links.ts, app-icons.ts): PASS (keeps installed apps and their permissions). - **Access**: sign-in (Better Auth core), agent grants (packages/mcp-auth), API keys, groups, sharing, account links, access policy (proofs, resource-policy.ts, packages/authorization). FAIL each: one store whose parts change each other's records (round 2, part 1). CLOSED.
- **Activity log**: one part (recording and reading the same table). CLOSED.
- **Builder**: server compile (worker-build.ts and helpers), browser build (worker-browser-build.ts, ui-build.ts), dependency install (worker-dependencies.ts), build storage (worker-build-storage.ts, worker-build-migration.ts), Cloud admission (build-admission.ts). FAIL each: steps of one compile pipeline, an adapter to the npm registry, and storage. CLOSED.
- **App sandbox**: runner (app-runner.ts), residency (app-worker-residency.ts), protocol adapters (app-protocols.ts), elicitation relay (worker-elicitation.ts), data facet supervisor (packages/app-data), workerd process transport (workerd-client.ts, remote-app-runner.ts, runtime-hop.ts, runtime-connect.ts), Cloud runtime actor. - **Outbound gateway**: credential placement (credential-handles.ts), address policy (app-network.ts, packages/utils/src/url-policy.ts), Cloud relay (app-outbound-*.ts). FAIL each: one decision path, split by deployment form. CLOSED.
- **Workflow engine**: one part. CLOSED.
- **Apps framework**: authoring API and schemas (index.ts, contracts/**), host handler (implementation/host.ts), storage (sql.ts), importers (mcp.ts, openapi*.ts, graphql.ts), cache (packages/app-cache), browser client (browser/**, ui-client.ts, live.ts, optimistic.ts, react.ts, desktop.ts, client.ts, under their own lint override). CLOSED.

Decision: no Level 3 component opens. Level 4 is decided: there is none. Stop.
