# Open list

Component guideline (use-boundary-model): a part is a component when it keeps state that only it changes, or makes decisions that only it makes, and the other parts reach it only through what it exposes. Clients that only present, parts that only pass requests on, storage, libraries and adapters to outside services are not components. Variants of one contract are one component with variants, separate from the part that chooses or uses them.

## Round 1 (Level 2): inside LangChain

Seams the code enforces (read myself):
- Each package is its own distribution with its own version, and declares langchain-core as a ranged dependency (libs/*/pyproject.toml, libs/partners/*/pyproject.toml). langchain-model-profiles depends on httpx only.
- libs/core/scripts/lint_imports.sh: core may not import `langchain.` (except docstring-style agents/tools lines) or `langchain_experimental`.
- libs/partners/*/scripts/lint_imports.sh: integrations may not import `langchain.` except `langchain.agents`, `langchain.chat_models`, `langchain.tools`.
- libs/langchain/scripts/lint_imports.sh: per-subpackage import rules inside langchain-classic, and no top-level `langchain_community` import without a marker.
- ruff `ban-relative-imports = "all"` in langchain_v1, standard-tests, model-profiles, text-splitters and most partners.
- No package outside libs/langchain imports `langchain_classic`; no package imports `langchain_tests` or `langchain_model_profiles` (git grep, non-test source).
- History: 415 of 464 commits that change package source change one package only; the frequent pairs are core+openai (17), anthropic+openai (16), core+anthropic (15), core+langchain_v1 (12), core+langchain (12) (git log --no-renames --name-only since 2026-05-25, lock files, version files and generated profiles left out).
