Parts of T3 Code, each tested against the component guideline:

1. Environment server (apps/server, with the provider-*, source-control-*, issue-tracker-linear, secret-provider-*, effect-acp, effect-codex-app-server, ssh, tailscale packages it loads) -> COMPONENT. Keeps all durable state of an environment (projects, threads, settings, sessions, scheduled tasks, workflow runs: apps/server/src/persistence/*, statev2.sqlite) and only it changes it; decides orchestration (apps/server/src/orchestration-v2/Orchestrator.ts). Others reach it only through its declared contracts: WebSocket RPC (packages/contracts/src/rpc.ts, orchestrationV2.ts) authorized per call in apps/server/src/auth/RpcAuthorization.ts, environment HTTP API (packages/contracts/src/environmentHttp.ts), MCP at /mcp registered only through apps/server/src/mcp/McpHttpServer.ts (lint rule no-raw-mcp-registration), guest routes (apps/server/src/guest/http.ts).
2. T3 Connect relay (infra/relay) -> COMPONENT. Keeps environment links, managed endpoint allocations, mobile device and Live Activity registrations, held webhooks (infra/relay/src/persistence/schema.ts, hooks/HookInboxObject.ts); decides tunnel allocation and who may get a connection credential (environments/ManagedEndpointProvider.ts, EnvironmentConnector.ts). Reached only through RelayApi (packages/contracts/src/relay.ts; infra/relay/src/http/Api.ts). Own deployment (infra/relay/alchemy.run.ts).
3. Client app (apps/web, apps/mobile, the desktop window's renderer which is apps/web, packages/client-runtime) -> COMPONENT (variants: web, desktop window, mobile; one client-runtime contract). Keeps the saved environments and their credentials, drafts, cached thread state and client preferences, and only it changes them (packages/client-runtime/src/connection/registry.ts, connection catalog; docs/internals/09_connection-runtime.md "explicit removal closes the scope and clears credentials, caches, and drafts"); decides which environment a new thread goes to (load balancing, docs/user/remote-access.md) and owns reconnects (connection/supervisor.ts). App views reach its state only through client-runtime's public subpaths (packages/client-runtime/README.md; vite.config.ts bans the root import; no-rpc-permission-bypass keeps raw RPC inside client-runtime/src/rpc).
4. Desktop shell (apps/desktop/src: Electron main process and preloads) -> COMPONENT. Keeps desktop state only it changes: whether the local environment runs and how it is exposed, WSL choice, SSH-launched environments, preview browser profiles and imported cookies, pending SnapShots, update channel (apps/desktop/src/settings/*, backend/DesktopServerExposure.ts, preview/BrowserImport/*, snapShot/*, updates/*); decides starting and stopping the local server (backend/DesktopBackendManager.ts). Reached by the window only through the typed desktop bridge (packages/contracts/src/ipc.ts DesktopBridge, apps/desktop/src/preload.ts, ipc/DesktopIpc.ts), and by the server only through the desktop browser channel (packages/contracts/src/desktopBrowser.ts).
5. t3.codes website (apps/marketing) -> NOT a component: static pages, download links built from GitHub releases (apps/marketing/src/lib/releases.ts), install scripts staged at build (scripts/stage-install-scripts.mjs); keeps no state and decides nothing -> part of an interface ("t3.codes website").
6. `t3` npm launcher (scripts/npm-launcher) -> NOT a component: downloads and runs the right `t3` release, passes requests on -> part of the command line interface.
7. Wire contracts (packages/contracts) -> NOT a component: schema definitions only ("No heavy runtime logic", AGENTS.md); a library that declares the interfaces.
8. Shared utilities (packages/shared) -> NOT a component: library.
9. Native helpers (native/*: libghostty-vt, kde-snap-shot, hyprland-snap-shot, resource-monitor, browser-secret, apple-speech) and the GNOME extension (apps/desktop/gnome-extension) -> NOT components: adapters the server and desktop shell use to reach the OS.
10. Shared task cache (infra/task-cache) -> engineering tooling, excluded.

Keeps provider instances' live sessions, sign-ins, managed runtimes and model catalogs (ProviderInstanceRegistry.ts, ProviderCredentialStore.ts, CodexManagedRuntime.ts, ModelManifest.ts); decides which instance serves a turn and what each declares (ProviderAdapterRegistry.ts). Only it writes sessions, pairing links, T3 Connect device approvals (persistence/AuthSessions.ts, AuthPairingLinks.ts, AuthConnectDevices.ts used only from auth/); decides every RPC's scope (auth/RpcAuthorization.ts) and MCP OAuth (auth/McpOAuth.ts). Only it writes task folders and worktree layout approvals (TaskFolderStore.ts, LayoutCommandApprovalWrites.ts); TaskFolders.ts is the only place layout commands run, and lint rule no-layout-command-approval-writes keeps approval writes to the client RPC. 5. Git (vcs/*, git/*, checkpointing/*, review/*) -> COMPONENT. Only it writes checkpoint refs (checkpointing/CheckpointStore.ts) and creates/removes worktrees (vcs/worktreeRemoval.ts, GitVcsDriver.ts); decides stacked commit/push/PR actions (git/GitWorkflowService.ts). Reached through VcsDriver (vcs/VcsDriver.ts, VcsDriverRegistry.ts), GitManager, CheckpointStore.

8. Workflows (workflows/*) -> COMPONENT. Only it writes workflow runs, steps, waits, triggers, hooks (WorkflowStore.ts); decides step execution and retries (WorkflowEngine.ts).
9. Linked environments (peer/*) -> COMPONENT. Only it writes peer links (PeerLinks.ts, table peer_environment_links); decides mode ceilings and forwarding (PeerForwarding.ts).

T3 Connect link (cloud/ link files: CloudLink.ts, CliTokenManager.ts, CliState.ts, ManagedEndpointRuntime.ts, RelayClientLedger.ts, linkChecks.ts, ConnectReachability.ts, http.ts; relay/*) -> COMPONENT. Keeps the environment's cloud credentials and its managed tunnel (cloudflared); decides which relay proofs to accept and mints bootstrap credentials for relayed clients (CloudLink.ts, docs/internals/06_t3-connect.md).
11. Terminals (terminal/*) -> COMPONENT. Keeps terminal sessions and their history, only it changes them (terminal/Manager.ts); reached through the terminal manager service.

### Round 2 decision: Client app -> STAYS CLOSED (one component-like part)
Parts tested:
- Connection runtime (packages/client-runtime/src/connection/*, authorization/*, environment/*, relay/*): keeps saved environments, their credentials and the T3 Connect sign-in; decides reconnects (supervisor.ts, registry.ts, catalog.ts, credentialStore.ts). Passes the test, but it is the only part that does.
- Shared client state (packages/client-runtime/src/state/*, platform/*, operations/*): caches of the server's projections and commands queued while offline; the environment's state wins on reconnect (docs/user/thread-sidebar.md "Pending ... the environment's state wins"; docs/internals/09_connection-runtime.md "Cached projections stay readable offline") -> a mirror of the server's resources, not a component.
- Web UI (apps/web/src), mobile UI (apps/mobile/src), desktop window (apps/web in apps/desktop): present the capabilities; drafts, prompt stash and client preferences are presentation state (apps/web/src/composerDraftStore.ts, promptStashStore.ts); choosing a machine for a new draft (apps/web/src/components/chat/useDraftEnvironmentRouting.ts) is an interaction of starting a thread -> part of the interfaces.
- Voice input controller (client-runtime/src/voice-input/*) and device viewer (client-runtime/src/device/*): present recording and a device stream; transcription is done by the device or by the environment -> not components.
- Mobile native modules (apps/mobile/modules/*): adapters to iOS/Android (widgets, Live Activities, push token) -> not components.
